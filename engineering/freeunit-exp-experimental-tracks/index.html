1. What the fork is

A fork of freeunitorg/freeunit used as an unattended-agent workbench. Rules in HERMES.md: never push upstream; the tracking branch mirrors upstream; branch names carry the task; fork CI is context for a review, never a substitute for upstream CI. Write identity is the GitHub App app/freeunit-agent[bot], installed on this fork and the research repo only. Merging stays human. Output layer: top-level findings/ (agent findings, verified marker), reviews/ (PR review notes, added by PR #5), digests/.

3. The four tracks the question asks about

3.1 TrueAsync — REMOVED upstream, not an active track

  • Not in this fork. No trueasync branch, PR or issue exists here.
  • It was removed from the server in 1.37.0: commit b20aeb78 ("php: remove

the TrueAsync code path", changelog 118b28f3), inside tag 1.37.0. The CHANGES 1.37.0 entry records why: the code targeted a zend_async_event_t API expected in PHP 8.5 core, which did not ship; the configure probe never succeeded; the code sat behind #if NXT_PHP_TRUEASYNC in every build and could not have compiled (it read async/entrypoint members that nxt_php_app_conf_t has not got and called an undefined nxt_php_extension_init()). The probe, the entrypoint target key and the TrueAsync test suite went with it.

  • Earlier history: 1.35.2 shipped a graceful-shutdown fix "for PHP workers in

TrueAsync mode" — that section is now the project's only TrueAsync trace in the tree besides the removal note.

  • KB correction. An older repos.md line listed freeunitorg/trueasync-experiment

("TrueAsync experiments (v3)"). gh api repos/freeunitorg/trueasync-experiment and a GitHub name search both return 404 / no result on 2026-10-13, and the org repo list does not contain it. Treat that line as stale. The real external project is the true-async org (true-async/php-async, a PHP core extension implementing the TrueAsync ABI); the FreeUnit repo has no dependency on it and no code path for it.

  • Older KB lines that say "TrueAsync not compiled" (artisan-worker-stubs,

opcache-inprocess-fork, fork-spawn-php, index docs/roadmap note) described the pre-1.37.0 state. Correct reading today: the path is gone, so "rebuild the module to get in-process jobs" is no longer a candidate route.

3.2 QuickJS — not a FreeUnit experiment; one build flag only

  • Only touchpoint in the whole tree: pkg/contrib/src/njs/Makefile configures

njs with --no-quickjs. The comment states that njs 1.0.1 recommends QuickJS, but that needs an external QuickJS / QuickJS-NG library, so the build keeps the baseline deterministic. No FreeUnit QuickJS runtime, module or PoC exists.

  • The only other QuickJS trace in our material is packaging, not product:

Alpine aports main/quickjs-ng (andypost MR !105133, upgrade to 0.15.1).

3.3 FreeUnit v2 (PoC)

  • FreeUnit v2 (PoC) — a separate track, Rust orchestrator + NTS PHP workers

on Revolt, hypothesis = hang detection by TGID polling + PING/PONG with no FFI and no PHP runtime change. PoC complete 2026-06-15, development stopped: 38/38 issues closed, 76 tests green, H1–H6 proven on PHP 8.5.7 NTS. Three related repos: freeunit2, freeunit2-fnb (Request.id multiplex), freeunit2-a4v ("fair three-way" vs RoadRunner and FrankenPHP). Nothing from v2 is in the server tree; the frontend role it aimed at is now held by the TLS/H3 module track on FreeUnit itself.

3.4 Syscall audit

  • Research: syscall-audit-kernel-requirements.md (2026-07-16, branch

pre-1.35.6): direct syscalls, glibc wrappers, namespace flags and the Docker seccomp interaction, plus seven recommendations.

  • The CI job exists and is advisory: .github/workflows/security-syscalls.yml

— "Security (Syscall Drift)", continue-on-error: true, matrix glibc/musl, runs pinned containers (debian:trixie-slim/alpine:3.22), captures the syscall set with test/syscalls/run-in-docker.sh, uploads it as an artifact even on failure, then diffs it against the committed baselines test/syscalls/baseline-linux-{glibc,musl}.txt. test/syscalls/README.md holds the four-step sequence (one commit) that makes the gate blocking.

  • The Docker/seccomp side has its own gate: security-seccomp.yml (AF_ALG

profile, hardening matrix, src/nxt_capability.*, nxt_credential, nxt_isolation).

  • The KB document's recommendation to make the syscall job blocking is therefore

partly done (job shipped, advisory) and partly open (no committed baseline from CI yet).

  • Recommendation 3 of that document (make capget failure non-fatal) is **done

and shipped in 1.37.0** (PR #254).
