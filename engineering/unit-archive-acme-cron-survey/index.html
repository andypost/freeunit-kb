Unit archive survey — ACME / cert / mTLS / scheduler

Source: local archive of nginx/unit (repo archived 2025-10-08 → complete, never stale). Full FTS survey, all branches. Date: 2026-09-11. Tool: tools/acme_cron_sweep.py + tools/gh_archive.py search.

Method: swept 1554 items + 8590 comments + 2217 reviews for six themes (ACME/LE, cert lifecycle/rotation, certificates config/API, mTLS/client-certs, scheduler/cron/jobs, TLS-module/SNI/OCSP), then read the top threads in full.

Headline findings

  1. No built-in ACME, no built-in scheduler — ever. Position has been

consistent for 5+ years: external tooling (certbot / sytemd / cron) + Control API. Both are open, unbuilt feature requests, not forgotten work.

  1. A working peer-credential mechanism already exists upstream — PR #307

(i4ki, 2019-09, merged) added SCM_CREDENTIALS/SCM_CREDS cmsg to pass credentials over the control socket and "IPC validations on obvious places". This is the direct ancestor of FreeUnit's nxt_controller_check_peer_cred() (SO_PEERCRED) gate. Upstream had the primitive since 2019; it did not ship an auth policy on top.

  1. mTLS promised in 2021, still absent. Maintainer VBart on #547

(2021-05-18): "Yes. Something similar to the ssl_verify_client and ssl_client_certificate directives in nginx is planned. No ETA yet, but likely will be implemented this year." Five years on, still open (#225).

Theme: cert lifecycle / rotation

  • #195 (open 2018) — the PUT-overwrite request == our X9 Step 1.

Current rotation is a manual dance: delete listener-assoc → delete cert → PUT → re-attach. Maintainer lcrilly (2023-12) confirms the delete-then-add flow.

  • #547 (closed 2021, but the substance is open) — **mTLS + rotation + cron in

one thread**: user runs "1 process: unit; 1 daemon/cron: pulling the new certificate … bundling … doing the curl". tippexs/VBart answer: use docker-entrypoint.d, s6-overlay, consul-template; no in-daemon scheduler. This is exactly the external-orchestration pattern our X10 proposes to internalise.

Theme: scheduler / cron / jobs

  • #1528 (closed 2025-01) — DECISIVE for X10: user wants to *"replace

Supervisor" and run Laravel queue/schedule long-running commands inside Unit. ac000 (maintainer, 2025-01-13): "I think this is really outside the scope of Unit. … Unit is a web application server and as such expects certain things."* → in-daemon scheduler actively rejected upstream. Code-level: external requires the libunit init handshake (NXT_UNIT_INIT env blob + nxt_unit_init()), so a plain worker hangs on reload and is untracked. Counter-argument + full X10 positioning: engineering/scheduled-tasks-plan.md § «X10 — upstream rejection (#1528) and why IPC emulation changes the calculus» (a thin libunit shim emulates the mandatory handshake; a persistent flag defeats the 15-s idle reaper).

Bottom line: ACME (#424) and PUT-overwrite (#195) are live upstream requests our plan addresses. Control-API auth (#307 primitive) and mTLS (#225/#547) are old promises. The in-daemon scheduler (X10) is upstream-rejected (#1528) — it is our differentiation, not catch-up. Peer-cred is not novel: it traces to merged PR #307 (2019); our contribution is the policy layer + TCP/mTLS.
