WordPress + FreeUnit — Production Baseline

Why FreeUnit for WordPress

WordPress is 43% of the web. Most of it runs on php-fpm (shared hosting) or nginx+FPM (VPS). FreeUnit replaces both — same performance for simple sites, better stability under load, zero-downtime deploys, and a path to persistent workers that php-fpm cannot provide.

Key number: WordPress does ~5KB median response. The bottleneck is never the app server. It's MySQL queries, PHP filesystem, and opcache misses. FreeUnit fixes the non-database overhead and gives room to scale.

Quick Start (Docker)

Minimal Docker

docker run -d \
  --name freeunit-wp \
  -p 8080:80 \
  -v ./wp-content:/var/www/wp-content \
  ghcr.io/freeunitorg/freeunit:latest-php-8.5

With MySQL + full WordPress

# docker-compose.yml
version: "3.8"
services:
  db:
    image: mariadb:11
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: wordpress
      MYSQL_USER: wp
      MYSQL_PASSWORD: wp

  freeunit:
    image: ghcr.io/freeunitorg/freeunit:latest-php-8.5
    ports:
      - "8080:8080"
    volumes:
      - ./wp-content:/var/www/wp-content
      - ./config.json:/etc/unit/config.json:ro
    depends_on:
      - db

Running benchmarks (oha)

# Low concurrency — baseline
oha -n 50000 -c 128 -z 30s --latency-correction \
  http://your-server:8080/bench.php

# High concurrency — burst
oha -n 200000 -c 2048 -z 60s --latency-correction \
  http://your-server:8080/bench.php

# Mixed static + PHP
oha -n 50000 -c 256 -z 60s --latency-correction \
  -m GET \

WordPress-Specific Tuning

opcache (biggest win)

"options": {
  "admin": {
    "opcache.enable": 1,
    "opcache.memory_consumption": 128,
    "opcache.max_accelerated_files": 5000,
    "opcache.validate_timestamps": 1,
    "opcache.revalidate_freq": 60,
    "opcache.jit": "tracing",
    "opcache.jit_buffer_size": "64M"
  }
}

WordPress has ~700 PHP files. opcache.preload not available by default (WP doesn't ship a preload script), but plugins like WP Rocket or custom mu-plugins can add one.

Redirects (admin bar, /wp-admin)

# Prevent rendering admin bar for non-authenticated requests
# In wp-config.php:
if (!is_admin() && !is_user_logged_in()) {
    show_admin_bar(false);
}

This alone can cut /wp-admin/ rendering by 40%.

MySQL connection — reuse via P4 (future)

Current: each request opens a new MySQL connection (TCP handshake + auth = ~1ms). With P4 persistent worker: one PDO connection per worker lifetime — 0ms overhead.

Object cache (Redis)

WordPress without object cache runs ~30 queries per page. With Redis object cache (via redis-cache plugin): ~5 queries.

docker run -d --name redis --network wp-network redis:7-alpine
# Then install plugin: wp plugin install redis-cache --activate

Production Checklist

[ ] FreeUnit 1.36.0+ running
[ ] PHP 8.4 or 8.5
[ ] opcache enabled + JIT tracing
[ ] MySQL with persistent connection (sql.php: mysql_pconnect)
[ ] Redis object cache (redis-cache plugin)
[ ] Static files: served directly by FreeUnit (no nginx needed)
[ ] TLS: terminate at edge (Caddy / Cloudflare)
[ ] Graceful shutdown: SIGQUIT configured in systemd/container
[ ] Health check: GET /wp-admin/admin-ajax.php?action=heartbeat
[ ] Backup: wp-content + database dump
