Correction to #323's timeline (the issue's own causal sentence is wrong)

The issue states: "The 2020 annotation was true when it was written. .php had no media type until 2021, so a share reaching a PHP file did not serve its source. A one-line MIME addition invalidated a security claim written eleven months earlier."

Wrong on the mechanism, as #323's own later section proves: an unfiltered share returns the bytes whatever the extension — with no MIME type the file is served with no Content-Type header, not withheld. What actually changed the documented config's reachability is the adoption of $uri in the Drupal share (57480b1f, 2021-11-18, three weeks after c5220944), because until then the shipped share was a bare directory.

The annotation was therefore false from the day it was written — the uri rule has matched case-sensitively since 2019-02, in the same commit that made the host rule case-insensitive. The 2021 MIME entry did not create the leak; it added the LABEL and made the !application/x-httpd-php filter expressible at all. Consequences for the write-up:

  • The MIME entry is neither the cause nor a candidate fix; #323 already reached this, and now

the earlier section should be corrected so the two halves stop contradicting each other.

  • VBart's 2024 "intentional" ruling answered the INDEX question, not the case vector, which was

never put to the project. It is not precedent for this report — as #323 says, but the precedence argument is stronger once the timeline is right.

  • The severity argument should stand on the 2021-11 documentation date, not on 2021-05.
