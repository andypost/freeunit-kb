Triage of #508/#515–#523

Security / DoS → must be in a patch (1.36.2)

PRWhatDraft?
#508http: add body_min_rate + send_min_rate — body_read_timeout/send_timeout are gap timers, so a byte just before each deadline holds a connection forever (slow POST / slow read). header_read_timeout is a single budget and is unaffected. This is the exact gap a min_body_rate closes.ready
#515fix(isolation): unshare the cgroup namespace after the cgroup move — with namespaces.cgroup: true the app's /proc/self/cgroup was rooted at the main process (0::/scope/python instead of 0::/). Containment.ready
#517wasm: check the guest malloc result against the linear memory size — the guest i32 was sign-extended into size_t, moved the host base below linear memory, and the first request wrote the header out of bounds. Sandbox memory corruption.draft
#520regex: cap a pattern's match work at 1,000,000 steps — pcre2_match() ran with no limit; ^/(.)/(.)[xy]$ backtracks quadratically → ~167 ms router CPU per request on an 8 KiB URI → ReDoS thread stall (and the log echoed the full URI).draft
#521isolation: create mount destinations without following symlinks — nxt_fs_mkdir_p() followed a symlink, letting a writable-rootfs app make the prototype create dirs outside the rootfs as root (escape); pre-openat2 it also mounted the unchecked path.draft
#522http: bound WebSocket pings answered per connection — the router PONGs every PING without waiting for the write side, so a PING-flood + slow read grows the pending write queue without limit. New option settings/http/websocket/max_pings.draft

Bugfix (not security) → next patch

PRWhatDraft?
#518php: free the root path buffer when realpath() fails (leak) + two wrong route comments.draft
#519port: never hand out RPC stream 0 after the 32-bit counter wraps — wrapped callers treat 0 as failure and skip nxt_port_rpc_cancel(), leaking handler registrations. Needs 2^32 ops to reach.draft

Feature / perf → minor (1.37.0)

PRWhatDraft?
#523 (issue #516)main: store the atomic state files in a short-lived child process — the two fsync() per stored file run in the event loop; a reconfigure on pro4s-4 took 19.1 → 42.2 ms and SIGTERM 5.0 → 17.4 ms.ready
