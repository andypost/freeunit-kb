### Draft, `CHANGES` style

```
    *) Bugfix: when a response body part travelled in the same message as
       the response fields, the router did not compress it.  libunit puts
       the first body part into the message that carries the fields when
       that message has room; with a response buffer over 1024 bytes it ends
       at a 16 KiB shared memory chunk boundary, so up to 16 KiB of body
       went to the client uncompressed.  Python WSGI, Python ASGI, Perl and
       Ruby applications send the fields with the first body write, so they
       were affected.  The body part is now compressed.  See
       https://github.com/freeunitorg/freeunit/issues/666.

    *) Bugfix: a request could be parked in an application for ever when a
       router engine thread was started with a connection already waiting in
       the listen backlog.  The thread posted the addition of its port to
       the main thread and started its event loop at once; a connection
       accepted before that work ran made the application ask for the engine
       port, and the router answered nothing.  "limits" "timeout" did not
       end it.  The engine port is now published before the thread starts.
       See https://github.com/freeunitorg/freeunit/issues/667.

    *) Bugfix: a worker that claimed a request from the shared queue and
       then failed before it acknowledged the claim left the request
       unanswered.  The router could not take it back, and the application
       timeout skipped claimed requests without re-arming, so with the
       default "timeout" of 0 the client waited for ever.  The router now
       logs an alert and answers such a request.  See
       https://github.com/freeunitorg/freeunit/issues/665.
```

## 2. The `off_t` entry in the XML

```xml
<change type="bugfix">
<para>
with a 32-bit libc, several source files had a 32-bit off_t and the other
files had a 64-bit off_t, so a struct with an off_t had different layouts in
different files.  On Linux, Solaris and HP-UX the files include a system
header before nxt_unix.h, which sets _FILE_OFFSET_BITS; on QNX nxt_unix.h
does not set the macro at all.  The "min_length" compression option was
written as 8 bytes into a 4-byte field, and build or tests crashed.  configure
now adds -D_FILE_OFFSET_BITS=64 on those four systems, and the build fails
when off_t does not have the size that configure measured.  musl and 64-bit
systems were not affected.
</para>
</change>
```

Place it second, to keep the XML's order equal to `CHANGES`.

## 3. The two `Change:` entries — wording for a patch-class release

Both entries describe work already merged into master, so the text must keep saying what shipped;
"cleaning" here means wording that makes clear nothing client-visible breaks, so the section reads
as patch-class. Two clauses do that; the classification itself stays the maintainer's call.

1. `--otel` no longer needs OpenSSL → add: _The exporter has linked no TLS stack since 1.36.0; this
   only changes what configure requires, and no running configuration is affected._
2. TLS failures caused by the client logged at `info` instead of `alert` → add: _Only the log level
   changes; the same connections are refused as before, with the same status in the same place._

If the maintainer prefers a strictly patch-clean section, the alternative is to move both entries to
the next minor's section in the same commit that bumps the version — but the code is in master
already, so the entry must not disappear silently; it must land in whichever section describes the
release that first carries it.
