Part 2 — quorum

Method: one identical prompt (evidence bundle: the train's measured state, gate results, the three known gaps, the six candidates with their sizes and conflict states) sent to every reachable model with temperature 0; each model asked for VERDICT: A|B|C|D (A = freeze the train, B = freeze plus non-behavioural adds, C = B plus the INI patch, D = C plus #638), plus WHY/SPOT/RISK/CONFIDENCE and a separate MINOR: patch|minor answer.

Window 2/4. Both valid votes picked freeze, both for the same reason: adding code with no build or test run on the release side is the one unacceptable risk when speed, accuracy and reliability must all hold, and the train is already the rehearsed, gated content.

Both valid voters also answered minor: the section's two Change: entries ("--otel" no longer needs OpenSSL; client-caused TLS failures logged at info) disqualify it from being called a patch under the project's own rule. That is the release's real decision — the version class, not the content list.

Divergence, and ground-truthing the SPOTs

  • qwen's SPOT — "the train's integrity is compromised because #586 is CONFLICTING" — is an artifact

of the prompt listing candidates and the train together. Refuted: the seven train PRs were each diffed and merge-tested against master in this session with 0 conflicts; #586 is outside the train.

  • gpt-oss-120b's SPOT — the off_t entry present in CHANGES but absent from docs/changes.xml —

agrees with the measured gap (3 hits vs 0). Confirmed, already on the fix list.

  • deepseek-v4-pro's reasoning (unstructured, but checkable) — that fixing one XML entry may still

leave a count mismatch once the three owed entries are added. Confirmed and worth acting on: today CHANGES 25 / XML 24 (the one-entry delta is exactly off_t). Adding the three owed entries to both files must land the pair at 28/28, and that check must be re-run, not assumed.

  • The two DeepSeek models are the ones the release actually depends on for review, and both failed

the output contract at max_tokens 4000 — a usable warning for the packet prompts: the structured answer must come before any reasoning, or the parse dies.

Part 3 — synthesis

  1. The quorum's A and this study agree on the content: **freeze on the rehearsed train; add only what

cannot change behaviour** (#656, #646, #657) if a reviewer covers them.

  1. The version class is unresolved and decides everything else. If the release stays a patch:

freeze exactly as quorum A, close the changelog gaps, tag. If it becomes a minor: #586 (size bounds, with the level overlap resolved against #674) and #12 (INI injection) belong in it with room to review, and #638 is still the following cycle.

  1. Non-negotiables for accuracy, independent of the version decision: the three owed entries, the

off_t XML entry, the 28/28 parity re-check, section header date, version bump.

Quorum caveat, stated plainly: two votes of a possible four, both from the same two vendors, with no Anthropic model in the window and both DeepSeek models outside the output contract. It is a useful signal, not a verdict from twelve reviewers.
